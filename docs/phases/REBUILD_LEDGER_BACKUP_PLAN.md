# Rebuild P03-02/07 — online ledger backup to new file

Plan before code: expose a synchronous storage primitive for future worker integration, not a production queue/UI feature. Use SQLite online backup to an owned temporary database in an explicitly chosen existing output directory, not raw copy of live DB files. Reject active source transactions to avoid deadlock/reentrancy. Explicit monotonic timeout (0<seconds<=60) and cancellation checked before work, during bounded-page backup progress and before publication. SQLite busy waits and filesystem fsync may not provide hard realtime cancellation; no descendant/process or network-filesystem deadline guarantee.

After backup, integrity_check must return exactly ok and version/schema must match current ledger. Flush closed owned staging, atomic no-overwrite hard-link to new target, clean only owned temp. Existing destination/symlink rejected and race protected by no-overwrite link. No overwrite/rename of source or destination and no guessed migrations. Record caller-visible return path only after validation/publication. Restore is separately opening that verified snapshot; running/interrupted state and immutable intents remain unchanged, no automatic replay.

Tests: backup/reopen retains intent/lease; expired restored lease becomes interrupted only on explicit reconciliation; existing output bytes unchanged; cancel/timeout/bad bounds before publication; active transaction rejected; backup failure cleans staging. No actual user database, secrets or network. Original JobStore schema/lease tests remain required.
