# Media-library persistence — bounded design review

2026-11-01 16:53 UTC. Read draft MEDIA_LIBRARY_PERSISTENCE_PROPOSAL.md and current Project/ProjectSession/recovery/relink/MediaObservation implementations. No source edits, tests or native execution.

Direction is appropriate: explicit project envelope v2, retain v1 serializer, use existing JSON-column CAS, separate unresolved library facts from executable CompositionPlan. This is design-entry guidance, not source acceptance.

## Decisions required in the first implementation

1. **Whole-project revision:** current ProjectSession.commit requires exactly next CompositionPlan revision. Library-only add/remove/relink/refresh must advance that revision exactly once and capture expected revision; no silent independent counter bypass. A duplicate no-op should not be represented as a completed mutation. Preserve plan UUID and project identity.
2. **Version and preservation:** use an explicit discriminator (e.g. absent library=None means v1, present immutable empty library means v2), not truthiness. Add a single preservation-safe with_plan/replacement helper. Audit direct constructors in autosave recovery and both relink commands; fixture/copy paths must not discard library. Test old composition-only changes on a populated v2 record, not merely v2 serialization roundtrip. V1 byte compatibility means preserving current canonical v1 serialization, not promising arbitrary original JSON whitespace retention.
3. **Identity policy:** stable library UUID is independent of legacy composition asset UUID. Recommended initial one-item-per-content policy: exact repeated import returns existing identity/no-op; same SHA with conflicting size/observation/path refuses implicit update, requiring explicit same-content refresh/relink. Duplicate UUID with different content always refuses. Do not infer a composition link by SHA or overwrite all same-content legacy assets automatically. If linkage is not implemented, state independence explicitly; root relink may deliberately enumerate both sets and update each matched reference atomically after every hash succeeds. Future replacement is a distinct command.
4. **Origins:** current autosave _relative, differs, recovery conversion and root-relink traversal only enumerate composition assets/fonts. Include library paths in every predicate and transform, including library-only relative references when composition has none. Existing row origin_base can serve both; no DB migration needed. Legacy unknown origin plus any relative library reference must refuse recovery rather than guess current file directory. Preserve same SHA/UUID while converting recovered paths. Native-incompatible Windows/Unix absolute paths remain unresolved, never silently interpreted relative to cwd. Save-As must retain existing restrictions until deliberately rebased.
5. **Typed trust and consistency:** dataclass type alone is not validation (MediaObservation currently accepts constructed values). Persisted reader and typed constructor must enforce identical field/type/range limits, render_ready exactly False, SHA equals item and path_ref hash, unique global stream indices/order, canonical rational denominator/sign/reduction, known basis/diagnostic enum semantics, matrix dimensions/int ranges and sanitized labels. Tick-derived start/duration must agree with stored ticks/timebase when basis says STREAM_TICKS. Do not manufacture unknown fields. A stored observation is historical content-bound information, not proof the current path still holds those bytes.
6. **Bounds:** preserve existing whole-project 33 MiB limit and enforce it on write as well as read before SQLite/file mutation; cap library count and serialized record size explicitly (chosen limits are admission/resource bounds, not media format rejection). Preserve current 256-stream bound. Exact 256-bit rational ceiling is sufficient for current <=128-bit base multiplied by signed64-bit ticks, but reader and typed writer must both apply it before expensive conversion. Bound decimal integer digits before int/Fraction, reject bool/float/noncanonical forms and surrogate Unicode safely. Avoid duplicating full unbounded asdict/JSON allocations before size checks.
7. **Compatibility/unknown outcomes:** no schema migration does not eliminate JSON-envelope migration risk. Existing v1 reader must reject v2; old stale writer must lose row CAS/file digest comparison after another process writes v2. Test that scenario and backup/restore Project.parse paths. Completed command must produce one fully validated immutable project before CAS; failed unknown save preserves session uncertainty and cannot return a partially updated library.

Recommended coherent first slice: pure validated library value + v2 Project roundtrip + all existing reconstruction/recovery/relink preservation + whole-project command/CAS regressions. Do not publish a v2 writer first while other current reconstruction paths silently erase it. Actual hash/probe admission and P04 media-bin UI remain separate; pure fixtures are not evidence of real source admission. No new criterion closure or full task acceptance follows from design review.
