# ADR-0001 — Clean rebuild technology decisions and experiment register

Status: PROPOSED unless explicitly marked. Owner: clean rebuild implementation owner; independent reviewer checks decisions. Deadlines are gates, not fabricated calendar estimates. Selected architecture: Python/PySide6 domain/application/UI separation, SQLite durable coordinator, FFmpeg/ffprobe media workers. These product-aligned choices permit pure logic implementation now; target tool versions and parity are not yet accepted.

## P02 local developer milestone (not full technology/target closure)

Fresh codee0cfb14 experiments verified Python3.12.14, PySide6 Essentials/Addons6.12.0, system FFmpeg7.1.5, JSON Schema4.26.0, Pillow13.0.0/NumPy2.3.5 and PyInstaller6.22.3 for isolated Linux experiments. Universal hash-locked experiment requirements are newly generated. Qt shared raster/layout is a viable candidate at640/1080 for synthetic text/shapes and same-frame encoded parity; full effect/time-map/audio/render/UI gates still required. Minimal Qt frozen Linux startup works; Windows packaging and installer NOT_RUN.

Default Qt audio-device enumeration crashes in this headless environment with missing PipeWire config; official PulseAudio selection avoids crash but finds0devices. This is an environment diagnosis, not proof of functional audio. UI must isolate optional device probing and report unavailable audio. [Official backend selection](https://raw.githubusercontent.com/qt/qtmultimedia/6.12/src/multimedia/platform/qplatformaudiodevices.cpp) and [Linux requirements](https://doc.qt.io/qt-6/qtmultimedia-linux.html) checked2026-11-01. No system-service/security changes. [Qt6.12 Windows configurations](https://doc.qt.io/qt-6.12/windows.html) list Windows10>=1809/11; user machine remains unknown and unverified.

## Bounded Windows tool reuse research (2026-11-01, no adoption)

`docs/dependencies/WINDOWS_FFMPEG_CANDIDATE.md` records an upstream-linked Gyan9.0.2
candidate with published archive SHA256, real community-package adoption, and open
quality concerns. Exact Windows packet-seek/cold-font behavior, advisory retrieval,
archive verification and redistribution provenance remain unresolved. This does
not replace the tested Linux developer7.1.5 binary or authorize an automatic system
install. P02-09/P03-08 distribution gates stay OPEN; safe local implementation can
continue independently without pretending an untested binary is production-ready.
